# Step 3: Data Testing

## Data Testing - Adding `data_check` Step

After the cleaning step, it is important to validate that the dataset is still reliable before proceeding to model training. Even if the pipeline runs without errors, the data itself may contain subtle issues such as unexpected distribution shifts or out-of-range values.

The validation rules live in `src/data_check/test_data.py`. The `data_check` MLflow component runs those rules with pytest when you connect it to the pipeline.

The fixtures in `src/data_check/conftest.py` record the validation runs in W&B with the job type `data_tests`. This is a W&B job label, not a separate MLflow component or a step to add to `main.py`.

You will complete the tests and add the `data_check` call so data validation runs before model training.

### Step 1: Define a Reference Dataset in W&B

To detect data drift, we need a **baseline dataset** to compare against.

Go to [wandb.ai](https://wandb.ai/) and:

1. Navigate to your **project → Artifacts** tab.
2. Open the `clean_sample` artifact type and locate the artifact named `clean_sample.csv`.
3. Select the artifact version with the `latest` alias.
4. In the right-hand panel, under **Aliases**, click the **+** button.
5. Add the `reference` alias to that artifact version.

Now the same dataset has two roles:

- `latest` → the most recent dataset produced by the pipeline
- `reference` → a stable baseline used for comparison

⚠️ For now, both point to the same data. Later, `latest` will change while `reference` remains fixed.

### Step 2: Write Data Tests

The `data_check` component executes the validation rules defined in `test_data.py`.

Open `src/data_check/test_data.py` and implement tests such as:

**Row Count Test**

```python
def test_row_count(data):
    assert 15000 < data.shape[0] < 1000000
```

This ensures the dataset size is within a reasonable range.

**Price Range Test**

```python
def test_price_range(data, min_price, max_price):
    assert data['price'].between(min_price, max_price).all()
```

This guarantees that all values fall within the expected boundaries.

⚠️ **Important**: The variable names must be exactly:

- data
- min_price
- max_price

### Step 3: Add the data_check Step to the Pipeline

Defining tests is not enough - they must be executed as part of the pipeline.

Update `main.py` to include the `data_check` step. This step will:

- Load the **current dataset** (`latest`)
- Load the **reference dataset**
- Run all tests defined in `test_data.py`
- Fail the pipeline if any test fails

Example parameters:

- `csv`: `clean_sample.csv:latest`
- `ref`: `clean_sample.csv:reference`
- `kl_threshold`: `config["data_check"]["kl_threshold"]`
- `min_price`: `config["etl"]["min_price"]`
- `max_price`: `config["etl"]["max_price"]`

Without this step, your tests exist but are never executed, and the pipeline cannot automatically detect data quality issues.

### Step 4: Run and Verify

Run the full pipeline:

```bash
mlflow run .
```

Or run only the data validation step:

```bash
mlflow run . -P steps="data_check"
```

If any test fails, the pipeline will stop immediately. This is expected and desirable - it prevents training models on bad data.
