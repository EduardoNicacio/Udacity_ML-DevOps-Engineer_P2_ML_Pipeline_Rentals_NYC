# Step 4: Initial Training

## Modeling and Evaluation Steps

### Step 1: Data Splitting

In this step, you will split the dataset into training/validation and test sets using the provided `train_val_test_split` component. To do this, you need to **modify** `main.py` and add the step to the pipeline.

Specifically:

- Locate the `if "data_split" in active_steps:` block in `main.py`
- Replace the placeholder code with a call to `mlflow.run(...)` using the `train_val_test_split` component

Use the following configuration parameters from the `modeling` section of `config.yaml`:

- `test_size`
- `random_seed`
- `stratify_by`

**Hint**: The path to the component can be written as:

```yaml
mlflow.run(f"{config['main']['components_repository']}/train_val_test_split", ...)
```

You can find the full list of accepted parameters in the [MLproject file](https://github.com/udacity/build-ml-pipeline-for-short-term-rental-prices/blob/main/components/train_val_test_split/MLproject).

After running the pipeline, you should see logs similar to:

```bash
Uploading trainval_data.csv dataset
Uploading test_data.csv dataset
```

This confirms that the following artifacts have been created and uploaded:

- `trainval_data.csv`
- `test_data.csv`

### Step 3: Optimize Hyperparameters

Re-run the **training step** while varying the hyperparameters of the Random Forest model. This can be done using Hydra’s **multi-run** feature by adding `-m` at the end of the `hydra_options` parameter. For this project, try the following settings:

- `modeling.max_tfidf_features`: `10, 15, 30`
- `modeling.random_forest.max_features`: `0.1, 0.33, 0.5, 0.75, 1`

This will launch a simple grid search with **15 runs** in total. Use the following command:

```bash
mlflow run . \
  -P steps="train_random_forest" \
  -P hydra_options="modeling.max_tfidf_features=10,15,30 modeling.random_forest.max_features=0.1,0.33,0.5,0.75,1 -m"
```

Before running this command, make sure the previous pipelin`e steps have completed successfully so that` trainval_data.csv:latest` is available.

You can monitor the runs in W&B and compare the model performance across different parameter combinations. While this basic grid search is sufficient for the project, you can also explore more advanced Hydra sweep options without modifying the pipeline code.

### Step 4: Select the Best Model

Go to **Weights & Biases (W&B)** to select the best-performing model from your runs.

![Selecting the best model](https://video.udacity-data.com/topher/2021/March/605103d6_wandb-select-best/wandb-select-best.gif)
<center>Selecting the best model</center>

### Step 5: Steps in W&B

1. Switch to **Table view** (second icon on the left).
2. Click **Columns** (upper right).
3. Click **Hide all** to remove unnecessary columns.
4. From the left list, select and add:
   - `ID`
   - `Job Type`
   - `max_depth`
   - `n_estimators`
   - `mae`
   - `r2`
5. Click **Close**.
6. In the table, click the three dots on the **mae** column header → **Sort ascending**.
   - This will order runs by Mean Absolute Error (MAE), with the best models at the top.
7. Click the run name of the best job → navigate to its artifacts → select the `random_forest_export` artifact version produced by that run.
8. In that version’s **Aliases** section, add the `prod` **alias** to mark this model as **production-ready**.

⚠️ **Important**: The pipeline refers to the model using `random_forest_export:prod`, which requires a **W&B alias**, not a tag. Using only a tag will cause the pipeline to fail when retrieving the model.

## Test the Production Model

Use the provided component `test_regression_model` to evaluate the production model on the test set. To do this, update the `if "test_regression_model" in active_steps:` block in `main.py`.

### Step 1: Set Parameters

Configure the step with the following parameters:

- `mlflow_model`: `random_forest_export:prod`
- `test_dataset`: `test_data.csv:latest`

You can find the full list of accepted parameters in the [MLproject file](https://github.com/udacity/build-ml-pipeline-for-short-term-rental-prices/blob/main/components/test_regression_model/MLproject)

⚠️ **Note**: This step is **not** included in the default pipeline execution. Before running it, you must manually promote a trained model artifact to the `prod` stage using a W&B **alias**. Using only a tag will not work.

Also make sure that the test dataset artifact exists in W&B and that its name matches the value used for `test_dataset`.

### Step 2: Run the Test Step Explicitly

```bash
mlflow run . -P steps="test_regression_model"
```

### Tip

Make sure the previous pipeline steps have completed successfully so that the test dataset artifact is available. Use the supplied dependency versions; change them only to resolve a reproduced dependency error.
